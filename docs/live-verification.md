## Что проверено

- Реальные отчёты имеют `source.type=github_api`, `mocked=false`.
- Проверены совпадение суммы дневных точек со статистикой и корректные границы
  значений; на повторных запросах молодых репозиториев проверены также сумма
  подозрительных звёзд и отсутствие ошибок отдельных проверок.
- Для DeepInfer график содержит 1068 подозрительных звёзд за 23 октября:
  1071 звезда при медиане предыдущих дней 3. Дополнительно сработал дисбаланс
  звёзд и разработки. Это объясняет score 67, но не доказывает накрутку:
  начало публичного продвижения после периода почти нулевой активности
  может приводить к ложному срабатыванию. Калибровка остаётся отдельной задачей.
- Несуществующий репозиторий возвращает HTTP 404 и `REPO_NOT_FOUND_ON_GITHUB`;
  `days=0` возвращает HTTP 400 и `INVALID_REQUEST`.
- Первый запрос Linux вернул 503, повторный — 200. Тело первого ответа не было
  сохранено, поэтому причина временного отказа не установлена.

  наблюдаемых было семь проверенных репозиториев. Следующий проход сохранил
  снимки всех семи без ошибок за 1108 мс.

## Найденная и исправленная ошибка

При перерыве обслуживания более трёх часов трекер не переносил в почасовую
историю более ранние сырые снимки, хотя они ещё хранились в БД. Это выявил
ранее пропускавшийся PostgreSQL-тест.

Теперь свёртка начинается с последнего сохранённого часа с двухчасовым
перекрытием, в пределах срока хранения сырых снимков. После свёртки сбрасывается
кеш общего суточного профиля. Регрессионный тест имитирует перерыв обслуживания
и предварительно заполненный кеш.

После исправления полный набор в Docker с доступом к Testcontainers:
**240 тестов, 0 failures, 0 errors, 0 skipped**. Тестовые базы были отдельными
от рабочей БД сервиса. Лог прогона: `/tmp/star-guard-verification.log`.

## Границы проверки

Исторический путь API и запись новых снимков проверены. Суточный профиль,
трёхдневный выход растущих и длительные чистки звёзд нельзя подтвердить коротким
живым прогоном без накопленной истории. Первичное заполнение топ-10 000 при
проверке шло медленно: дамп JVM показал ожидание GitHub Search; обычный опрос
наблюдаемых репозиториев при этом выполнялся отдельно.

Сборщик подозрительных аккаунтов в основном сервисе выключен. Его автоматические
тесты, включая PostgreSQL, прошли, но живой сбор пула и ненулевые совпадения
в отчёте в этом прогоне не проверялись. Прогон не является измерением
precision/recall и не подтверждает правильность ярлыков для этих репозиториев.

Исправленный образ установлен в основной контейнер; приложение и PostgreSQL
имеют статус healthy, `/actuator/health` отвечает UP. После пересоздания
сохранены семь наблюдаемых репозиториев и результаты предыдущего опроса.
Первичный поиск топа после перезапуска начинается заново; его завершение
в этом прогоне не подтверждено.
