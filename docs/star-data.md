# Откуда берём данные о звёздах

Используем два взаимодополняющих источника: дневную историю из GitHub API
и собственные регулярные снимки счётчиков. Это позволяет анализировать прошлое
репозитория сразу, а после начала наблюдения — видеть изменения внутри дня.
Ниже описано поведение реализации и настройки по умолчанию, не состояние
запущенного сервиса.

## Дневная история — из GitHub API

При проверке репозитория `GithubHistoryService` обращается к REST-методу
`GET /repos/{owner}/{name}/stargazers/history`. Ответ содержит недельные блоки
с массивом значений по дням; из них собираем дневной ряд в UTC.

По умолчанию загружаем историю за последние 180 дней, но не раньше создания
репозитория. Оценка строится за последние 30 дней или более короткое окно,
указанное в запросе. Предыдущие дни нужны для сравнения с обычным темпом роста.
Результат кешируется на пять минут. Дополнительно через GraphQL получаем текущие
числа звёзд и форков, дату создания и показатели активности проекта.

Это агрегированная история: она показывает распределение звёзд по дням,
но не раскрывает аккаунты и точное время каждой звезды. Для её загрузки
не требуется заранее включать репозиторий в наш трекер.

## Внутридневная история — собственный трекер

Каждые пять минут запрашиваем через GraphQL текущие `stargazerCount` и `forkCount`,
пакетами до 100 репозиториев. Сохраняем время и значения в PostgreSQL.
Под наблюдением находятся три пересекающиеся группы:

Все числа ниже — настройки по умолчанию. Расписание указано в UTC.

| Условие | Популярные | Быстрорастущие | Проверенные пользователями |
| --- | --- | --- | --- |
| Размер группы | Цель — **10 000** репозиториев с наибольшим числом звёзд; при нехватке лимита список может быть меньше. | Не более **3000** с флагом `rising`. | Порог приёма новых записей — **5000** наблюдаемых вне топа. |
| Условие входа | Попадание в результат отбора топа через GitHub Search по числу звёзд. Фиксированного минимального числа звёзд для попадания в топ нет. | Все условия одновременно: создан не раньше даты **30 дней назад**, имеет **≥100 звёзд**, `stars / max(1, полных дней с создания) ≥100`. | Построение GitHub-отчёта вызывает постановку на наблюдение; порогов по возрасту, звёздам и score нет. Также возможна явная постановка через трекер. |
| Когда ищем новых | Каждый день в **03:30**; при старте приложения — если сохранённый список популярных пуст. | При старте и каждый час в **HH:20**. | При каждом построении GitHub-отчёта, включая использование кеша истории. |
| Когда начинаем снимать счётчики | В ближайшем общем цикле опроса. При старте первоначальный опрос следует за обновлением пустого топа и поиском растущих. | В ближайшем общем цикле опроса после установки `rising=true`. | В ближайшем общем цикле опроса после добавления записи. |
| Частота опроса | **5 минут** между завершением одного планового прохода и началом следующего. | Та же: **5 минут**. | Та же: **5 минут**. |
| Что продлевает наблюдение | Присутствие в обновлённом топе. | Флаг остаётся, пока не выполнено условие выхода. Возраст **>30 дней** сам по себе его не снимает. | Каждая новая проверка продлевает `watched_until` до **30 дней** от момента проверки. |
| Условие выхода из группы | В очередном обновлённом списке репозиторий больше не входит в топ. | Чистый прирост за сутки **<20 звёзд**, и с первого обнаружения такого замедления прошло **≥3 суток** без обнаруженного восстановления. | Истёк срок **30 дней** после последней проверки. |
| Когда проверяем выход | При обновлении топа. | В обслуживающем цикле: первый через **10 минут** после старта, далее через **1 час** после завершения предыдущего. | Активность определяется на каждом опросе по `watched_until`; удаление просроченной записи — в обслуживающем цикле. |
| Что отменяет выход | Репозиторий снова попал в топ или остался в другой активной группе. | Прирост **≥20 звёзд за сутки** сбрасывает таймер замедления. Если суточного снимка ещё нет, проверка выхода пропускается. | Новая проверка до очистки продлевает срок; после удаления можно попасть в трекер заново. |
| Когда полностью прекращаем опрос | Только если одновременно нет места в топе, флага `rising` и действующего `watched_until`. | То же общее условие. | То же общее условие. |

Группы пересекаются: один репозиторий опрашивается **один раз за проход**, даже
если входит во все три. Число 5000 — ограничение при добавлении ранее неизвестной
записи: продление/включение наблюдения для уже существующей записи не блокируется
этим порогом. Поэтому **18 000 нельзя считать строгим общим потолком**.

Для быстрорастущих возраст при поиске задаётся календарной датой UTC, а темп
считается по **полным дням**, округлённым вниз, с минимумом в один день:

| Пример | Расчёт | Результат |
| --- | --- | --- |
| Возраст 6 часов, 100 звёзд | `100 / 1 = 100` | Проходит входной порог. |
| Возраст 2 дня 20 часов, 200 звёзд | `200 / 2 = 100` | Проходит; это приближение, не точная средняя скорость. |
| Возраст 5 дней, 400 звёзд | `400 / 5 = 80` | Не проходит. |
| За сутки прибавилось 19 звёзд | `19 < 20` | Начинается или продолжается отсчёт замедления. |
| За сутки прибавилось ровно 20 звёзд | `20 ≥ 20` | Отсчёт замедления сбрасывается. |

Суточный прирост для выхода сравнивает текущий сохранённый счётчик с последним
почасовым значением **не позднее 24 часов назад**. При пропусках интервал может
оказаться длиннее суток. Три дня замедления проверяются дискретно, примерно раз
в час, а не непрерывно. После снятия флага репозиторий может снова пройти входной
фильтр: отдельного запрета на повторный вход сейчас нет.

### Общие параметры сбора и хранения

| Параметр / событие | Число или условие | Поведение |
| --- | --- | --- |
| Запуск трекера | `app.tracker.enabled=true`, PostgreSQL, непустой `GITHUB_TOKEN` | По умолчанию трекер выключен; без токена опрос не планируется. |
| Размер пакета GraphQL | До **100 репозиториев** | Получаем текущие числа звёзд и форков по постоянным node ID. |
| Только топ-10 000 | **100 пакетных запросов** на полный проход | Расчёт числа запросов, не обещание стоимости в очках GraphQL; дополнительные группы увеличивают число пакетов. |
| Резерв лимита | **500 очков** | Если полученный в текущем проходе остаток **<500**, следующие пакеты этого прохода не отправляются. |
| Ошибка авторизации или rate limit | `GITHUB_TOKEN_REQUIRED` / `GITHUB_RATE_LIMITED` | Оставшиеся пакеты текущего прохода прекращаются; планировщик сохраняется. |
| Прочий обработанный сбой пакета | До **100 репозиториев** без нового снимка | Пакет учитывается как неуспешный; обработка следующих пакетов продолжается. |
| Репозиторий отсутствует в ответе опроса | Node не найден клиентом | Текущая реализация удаляет запись из трекера; сам факт недоступности не доказывает удаление репозитория или накрутку. |
| Сырые снимки | **26 часов** | Значения с шагом опроса для анализа внутри дня. |
| Почасовые значения | **8 дней** | Последний снимок каждого часа; суточный профиль строится за **7 дней**. |
| Обслуживание | Через **10 минут** после старта, затем с задержкой **1 час** | Пересчёт последних **3 завершённых часов**, проверка замедления, очистка старых снимков и неактивных записей. |
| Дневная история из REST | До **180 дней**, не раньше создания | Загружается при проверке репозитория, независимо от наличия в трекере. |
| Окно GitHub-отчёта | От **1 до 30 дней**, по умолчанию **30** | Более ранняя часть истории используется как база для сравнения. |
| Кеш GitHub-истории | **5 минут** | Повторный запрос может использовать кеш; постановка на наблюдение всё равно выполняется. |


Под «подозрительными» здесь правильнее понимать быстрорастущие и проверяемые
репозитории: отдельного автоматического отбора в трекер по высокому risk score
сейчас нет. Быстрый рост сам по себе не означает накрутку.

## Что дают снимки и где их границы

Разность соседних счётчиков показывает чистое изменение числа звёзд:
новые звёзды минус снятые. По ней ищем короткие всплески, падения и особенности
суточного ритма. Это не список отдельных действий: одновременное выставление
и снятие звёзд может взаимно компенсироваться.

Сырые снимки храним 26 часов, почасовые значения — восемь дней. История внутри
дня появляется только с начала наблюдения; восстановить её задним числом
из дневных агрегатов нельзя. При ошибках API или нехватке лимита возможны пропуски.
Трекер оставляет резерв очков GraphQL и фиксирует результат каждого опроса.

## Связь с пулом аккаунтов и включение

Пул подозрительных аккаунтов — отдельный механизм: он получает кандидатов
из форков отслеживаемых репозиториев и сохраняет последние 100 звёзд каждого
подходящего аккаунта с временем. Эти данные позволяют дополнить агрегатный
график конкретными совпадениями. Подробнее: [account-pool.md](account-pool.md).

Трекер по умолчанию выключен. Для работы нужны `app.tracker.enabled=true`,
PostgreSQL и `GITHUB_TOKEN`. Основные настройки: `app.tracker.*`,
`app.tracker.rising.*` и `app.github.history.*` в `application.yaml`.
Текущую статистику наблюдения отдаёт `/api/v1/tracker/status`.
