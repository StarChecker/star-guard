# Star Guard — расширение для Chrome

Показывает признаки накрутки звёзд прямо на GitHub:

- **значок у кнопки Star** — цвет уровня и score 0–100; по клику — к карточке;
- **карточка в сайдбаре** под About — вердикт, кольцо score, график звёзд
  (обычные / подозрительные), пять проверок с причинами, раскрываемые детали
  (репозитории с той же аудиторией звёзд, статистика окна);
- **точки в списках** — рядом со счётчиком звёзд в Trending, поиске, звёздах
  пользователя и репозиториях организации (только репозитории из индекса);
- **репозиторий вне индекса** — серый значок и кнопка «Проверить»: сервер
  сканирует GH Archive в фоне, карточка показывает прогресс;
- **popup** по иконке — та же карточка для текущей вкладки; **настройки** —
  адрес сервера, окно анализа, точки в списках.

Работает в Chrome и браузерах на Chromium (Edge, Яндекс Браузер, Arc).
Светлая и тёмная темы берутся из CSS-переменных GitHub (Primer).

## Установка (без магазина)

1. Запустить бэкенд (по умолчанию `http://localhost:8080`).
2. `chrome://extensions` → включить «Режим разработчика» → «Загрузить распакованное»
   → выбрать папку `extension/`. Готовый zip собирает CI (артефакт `star-guard-extension`).
3. Открыть любой репозиторий на GitHub.

Для сервера не на localhost — указать адрес в настройках расширения
(иконка Star Guard → «Настройки» → «Адрес сервера», там же «Проверить соединение» и «вернуть»
адрес по умолчанию): браузер попросит разрешение на этот домен.

## Сборка и адрес сервера по умолчанию

Адрес по умолчанию лежит в `src/config.js` (`http://localhost:8080`). Архив собирает
`scripts/pack-extension.sh [out.zip]`; если задать `STAR_GUARD_API_URL`, скрипт подставит
этот адрес в `config.js` и добавит его origin в `host_permissions` — разрешение спрашивать
не придётся. В CI и на лендинге адрес берётся из переменной репозитория `STAR_GUARD_API_URL`
(Settings → Secrets and variables → Actions → Variables).

Собранный архив лежит в `site/star-guard-extension.zip`; лендинг (`site/`, публикуется в
GitHub Pages workflow `pages.yml`) раздаёт свежую сборку по адресу
https://starchecker.github.io/star-guard/ — на него ведёт QR-код `site/qr.svg`.

## Как устроено

| Файл | Что делает |
|---|---|
| `manifest.json` | Manifest V3; content script только на `github.com` |
| `src/background.js` | service worker: все запросы к API, кэш (отчёт 5 мин, сводки 10 мин); принимает только сообщения фиксированных типов с проверенным `owner/name` |
| `src/content.js` | определяет страницу репозитория (`meta[name=octolytics-dimension-repository_nwo]`), встраивает значок, карточку и точки; переживает Turbo-навигацию GitHub (`turbo:load`, `MutationObserver`) |
| `src/ui.js` | отрисовка в Shadow DOM, только `textContent` — данные API не попадают в `innerHTML` |
| `popup.html`, `options.html` | popup и настройки |
| `preview/index.html` | все состояния интерфейса на примерах данных — для дизайн-ревью |

Запросы к API идут из service worker, а не из content script: из content script
кросс-доменный запрос упирается в CORS даже при `host_permissions`.

Используемые эндпоинты: `GET /api/v1/repos/{owner}/{name}`, `POST /api/v1/repos/batch`,
`POST /api/v1/scans`, `GET /api/v1/scans/{id}`, `GET /api/v1/preview/{owner}/{name}`
(статистика GitHub, пока оценки нет), `GET /api/v1/index/repos` (popup и проверка связи).

## Ограничения

- Вёрстка GitHub меняется; точки встраивания подобраны с запасными вариантами,
  а если сайдбара нет — карточка открывается плавающей панелью по клику на значок.
- Точки в списках рисуются только для репозиториев из индекса (топ-N за окно):
  прямой скан для каждого репозитория списка слишком дорогой.
- Пока C1 и C5 — моки, карточка помечает их тегом «демо».
